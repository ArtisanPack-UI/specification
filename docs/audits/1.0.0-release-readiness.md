# `artisanpack-ui/specification` — 1.0.0 Release Readiness Audit

- **Branch audited:** `release/1.0` @ `72bbfe7` (working tree clean)
- **Date:** 2026-10-10
- **Scope:** correctness, security, front end (rendered HTML/Markdown output, a11y, i18n), back end (sync, index, registry, MCP client, commands), release hygiene
- **Baseline:** `./vendor/bin/pest` → 206 passed (660 assertions). `php-cs-fixer --dry-run` → 0 files. `phpcs` → clean.
- **Live-data validation:** the real upstream bundle (`https://specification.website/okf.tar.gz`, 384 KB, 718 files, 173 `type: Check` topics, `okf_version: "0.2"`) was synced through a throwaway Pest probe. It synced cleanly (173 created, 0 errors). Findings marked **[confirmed]** were reproduced against the real bundle or with a probe.

## How to Use This Document (for the fixing agent)

1. Work on a single branch off `release/1.0` (e.g. `fix/1.0-release-audit`), with one commit per finding ID.
2. Each finding has **Where**, **Problem**, **Fix**, **Tests**, and **Done when**. Follow them in order of severity.
3. Code style: real tabs, WordPress-style spacing (`foo( $bar )`, `[ 'k' => $v ]`), Yoda conditions, full PHPDoc with `@since 1.0.0`, and every user-facing string wrapped in `__()`.
4. Format with `./vendor/bin/php-cs-fixer fix`. **Never run `pint` in this package.** Then run `./vendor/bin/phpcs` and `./vendor/bin/pest`.
5. Update `docs/` in the same branch where a finding changes behaviour (the docs are part of the release PR).
6. Before you finish, add the CHANGELOG entry (H3) that covers everything that landed.

## High

### H1 — Relative links in topic bodies render as broken links **[confirmed]**

**Where**
- `src/Attribution/SpecTopicRenderer.php:50-61` (converter setup)
- `src/Attribution/RenderedTopic.php:77-85` (`toHtml()`), `:94-97` (`toMarkdown()`)
- `src/Okf/TopicParser.php:43` (`SOURCE_KEYS` drops `mirror`), `:144-175` (`sources()`)

**Problem**
All 173 upstream Check bodies contain relative links, in two forms:
- `../references/<source-id>.md`. Every topic has at least one, e.g. `Primary standard: [HTML Living Standard — The DOCTYPE](../references/html-living-standard-the-doctype.md)`.
- Root-relative `/spec/<category>/<topic>/`, e.g. `/spec/security/content-security-policy/`.

Rendering `foundations/doctype` produces `href="../references/html-living-standard-the-doctype.md"`. In the host app this resolves against the host's own URL, so it is a broken link (or a link to an unrelated page). `/spec/...` links point at the host site, not at specification.website. Agent-surface Markdown (`toMarkdown()`) carries the same relative links.

**Fix**
1. Add a small `final class TopicLinkResolver` in `src/Attribution/`, built per topic from `slug`, `category`, `resource_url`, and `sources_json`. It exposes `resolve( string $url ): ?string`:
   - Absolute `http(s)://` URL, `mailto:`, or fragment-only (`#...`): return it unchanged.
   - Path matching `#(?:^|/)references/([a-z0-9-]+)\.md(?:\#.*)?$#`: look up the source whose `id` equals the captured id and return its `resource`. If there is no match, return `null`.
   - Root-relative `/...`: return `Attribution::SOURCE_URL . $url`.
   - Other relative `*.md` (`hsts.md`, `../security/hsts.md`): resolve against `okf/{category}/`. If the result matches `okf/{cat}/{topic}.md`, return `Attribution::SOURCE_URL . '/spec/{cat}/{topic}/'`. Otherwise return `null`.
   - Anything else that is relative: resolve against the topic's `resource_url` (`https://specification.website/spec/{cat}/{topic}/`).
2. In `RenderedTopic::toHtml()`, stop calling `$converter->convert()` directly. Parse with a `MarkdownParser`, walk the document, and for each `League\CommonMark\Extension\CommonMark\Node\Inline\Link` call `setUrl()` with the resolved URL. When the resolver returns `null`, replace the `Link` node with its children (unwrap it to plain text). Then render with `HtmlRenderer`. Keep `html_input: escape` and `allow_unsafe_links: false` on the environment. `SpecTopicRenderer` should build and hold the environment, parser, and renderer once, and pass the resolver into `RenderedTopic`.
3. `toMarkdown()`: apply the same resolution to the Markdown output. The simplest safe approach is to reuse the parsed document and rewrite the link destinations in the source text using the source positions from `Link::getStartLine()`. Alternatively, run a conservative regex `\]\(([^)\s]+)\)` that skips fenced code blocks. Either way, agent consumers must get absolute URLs.
4. Image nodes (`Image`): apply the same resolver to their URLs for consistency. No current topic has images.
5. Optional but recommended: `TopicParser` can keep `mirror` in `SOURCE_KEYS` so the mapping does not rely on `id` matching the file name. Today it does match for every topic in the bundle.

**Tests** (`tests/Feature/Attribution/AttributionTest.php` or a new `TopicLinkResolverTest.php`)
- A body with `[x](../references/<id>.md)` and a matching source renders `href="<source resource>"`.
- A body with `[x](../references/unknown.md)` renders the plain text `x` with no `<a>`.
- A body with `[x](/spec/security/hsts/)` renders `href="https://specification.website/spec/security/hsts/"`.
- A body with `[x](hsts.md)` in category `security` renders `href="https://specification.website/spec/security/hsts/"`.
- `[x](javascript:alert(1))` still has no `javascript:` href (regression guard).
- `toMarkdown()` contains no `](../` or `](/spec` destinations.
- Add one real-shaped fixture body to `tests/Fixtures/okf/foundations/doctype.md` with a `Primary standard: [...](../references/html-living-standard-the-doctype.md)` line, as upstream has.

**Done when** rendering any topic from the real bundle produces only absolute `https://` hrefs (or unwrapped text), and `docs/usage/rendering-topics.md` documents the link rewriting.

### H2 — Unvalidated attribution `href` / MCP URL → `javascript:` XSS **[confirmed]**

**Where**
- `src/Attribution/Attribution.php:67-71` (constructor), `:191-196` (`link()`)
- `src/Mcp/McpTopic.php:93` (`self::string( $data, 'url' )`)
- `src/Okf/TopicParser.php:190-199` (`resourceUrl()`, which has the correct origin check but is private)

**Problem**
`Attribution::link()` runs the href through `e()`, which HTML-escapes but does not neutralise the `javascript:` scheme. `McpTopic::fromArray()` accepts any non-empty string as `url`, and `McpTopic::attribution()->toHtml()` emits it. Probe output:

```html
<p class="spec-attribution">“<a href="javascript:alert(1)">T</a>” from …
```

A compromised or spoofed MCP response, or any caller that builds `new Attribution( $title, $userUrl )`, gets script execution in whatever admin/editor page displays the attribution. The docs present `toHtml()` as "escaped HTML" that is safe to output unescaped.

**Fix**
1. Move the origin check into `Attribution` as a public static helper:
   ```php
   public static function canonicalUrl( string $slug, mixed $url ): string
   ```
   It returns `$url` only when it is a valid absolute `https://specification.website/...` URL (the same rule as `TopicParser::resourceUrl()`). Otherwise it returns `self::SOURCE_URL . '/spec/' . $slug . '/'`. Make `TopicParser::resourceUrl()` delegate to it.
2. `McpTopic::fromArray()`: pass the URL through `Attribution::canonicalUrl( self::localSlug( $category, $slug ), $data['url'] ?? null )` instead of `self::string( $data, 'url' )`. A missing or foreign URL then falls back to the derived canonical URL rather than throwing. Update the `@throws` and docblock.
3. Defence in depth in `Attribution::link()`: if `parse_url( $href, PHP_URL_SCHEME )` is not `http` or `https`, return `e( $text )` with no anchor. Apply the same rule in `toMarkdown()`: drop the link and keep the escaped text. In `toMarkdown()`, also strip `<`, `>`, and whitespace from the URL inside `(<...>)`.

**Tests**
- `McpTopic::fromArray( [... 'url' => 'javascript:alert(1)' ] )->url` equals `https://specification.website/spec/y/x/`.
- `McpTopic::fromArray( [... 'url' => 'https://evil.example/x' ] )->url` falls back as well.
- `( new Attribution( 'T', 'javascript:alert(1)' ) )->toHtml()` contains no `href="javascript:`, and `toMarkdown()` contains no `javascript:`.
- Existing valid URLs are unchanged (regression).

**Done when** no `Attribution` output can contain a non-http(s) href, and `docs/usage/mcp-client.md` notes that URLs are normalised to the upstream origin.

## Medium

### M1 — `DoctypeCheck` "misplaced" detection matches anywhere, and the autofix deletes content **[confirmed]**

**Where** `src/Checks/Foundations/DoctypeCheck.php:178-194` (`inspect()`), `:243-256` (`fix()`)

**Problem**
When the document does not start with a doctype, `inspect()` searches the whole document for `<!doctype\b[^>]*>`. Matches inside `<script>`, `<style>`, `<textarea>`, comments after the first element, or plain text classify the page as "misplaced" instead of "missing". The autofix then removes that text. Probe:

```
input : <html><head><script>var t = '<!DOCTYPE html>';</script></head></html>
result: "The doctype is not the first thing in the document…"
fixed : <!doctype html>\n<html><head><script>var t = '';</script></head></html>
```

The fix silently changes page JavaScript. This is the reference check that owner packages are told to copy.

**Fix**
1. Compute a boundary: the offset of the first real start tag after the preamble. That is the first `<` followed by `[A-Za-z]` at or after `preambleLength()`. If there is none, use `strlen( $html )`.
2. Only look for a misplaced doctype **before that boundary**, and skip comments. For example, run the existing regex on `substr( $html, 0, $boundary )` with comments blanked out to equal-length spaces so the offsets stay valid.
3. If no doctype is found before the boundary, the state is `missing`. Never remove text at or after the boundary.
4. Update the class docblock to describe the rule.

**Tests** (`tests/Feature/Checks/DoctypeCheckTest.php`)
- A doctype inside `<script>` gives state `missing`, the message is "has no doctype", and the autofix output keeps the script content unchanged.
- A doctype inside a comment after `<html>` gives `missing`, and the comment is preserved.
- Text before the doctype (`hello<!doctype html><html>`) is still `misplaced`, and the fix removes it there (existing behaviour preserved).
- All existing DoctypeCheck tests still pass.

### M2 — One bad check aborts the whole run

**Where** `src/Checks/CheckRegistry.php:120-149` (`all()`), `src/Checks/CheckRunner.php:53-70`, `src/Console/Commands/SpecCheckCommand.php:99-106`, `src/SpecificationServiceProvider.php:138-140`

**Problem**
`CheckRegistry::all()` resolves every class-string check and validates every slug, and it throws on the first failure: an `InvalidCheckException` for a bad slug, or any container exception for an unresolvable dependency. `CheckRunner::run()` calls `forScope()`, which calls `all()`. So a single misbehaving owner-package check makes `specification()->run()` throw for every check. That contradicts the runner's documented guarantee ("A check that throws … produces an Errored result instead of aborting the run"). `keystone:spec-check` turns it into a bare error with no results.

Separately, an invalid class in `artisanpack.specification.checks` throws inside the `callAfterResolving` hook. That breaks resolving `Specification` itself, so `sync()`, `search()`, and `render()` fail too.

**Fix**
1. `CheckRegistry::all()`: wrap resolution and slug validation per check in `try/catch ( Throwable )`. On failure, `report( $exception )`, record `$this->invalid[ $class ] = $message`, remove the entry from `$this->checks`, and continue. Add `public function invalid(): array` (`array<class-string, string>`).
2. `register()`: keep throwing for a non-`SpecCheck` class (programmer error at registration time), but in the provider's config hook catch `InvalidCheckException`, `report()` it, and record it as invalid. Bad config should not break unrelated APIs.
3. `SpecCheckCommand`: after building `$checks`, print each `$registry->invalid()` entry as an error row and return `FAILURE` if any exist (so CI still gates), while still running and printing the valid checks.
4. Update `docs/advanced/authoring-checks.md` and `docs/usage/running-checks.md`.

**Tests**
- Registering one valid check and one with slug `Bad Slug` means `run()` returns the valid check's result, and `invalid()` lists the bad class.
- A check whose constructor dependency is unresolvable is reported in `invalid()`, and the others still run.
- An invalid class in config does not stop `specification()->search()` from working.
- `keystone:spec-check` with one invalid and one passing check prints the passing result and exits with `FAILURE`.

### M3 — Search index is per node, and only the syncing node rebuilds it

**Where** `src/Specification.php:95-98` (`search()`), `src/Okf/Synchronizer.php:142-147`, `src/Search/SqliteFtsIndex.php:162-167`

**Problem**
Topic rows live in the shared app database, but the FTS index (and the snapshot) is a local file under `storage_path()`. The scheduled sync runs on one node. On multi-server or ephemeral-filesystem deployments (Forge with several web nodes, Vapor, containers), every other node has an empty index. `search()` returns `[]` with no error, and nothing ever rebuilds it, because the "unchanged" fast path in `Synchronizer` only rebuilds the index on the node that runs the sync.

**Fix**
1. In `Specification::search()` (or a decorator around `SearchIndex`), compare `$this->index->version()` with `Snapshot::current()?->version`. If they differ and a snapshot exists, rebuild from `Topic::query()->orderBy( 'slug' )->get()` before searching. Guard the rebuild with a cache lock (`artisanpack-specification-index-rebuild`, short TTL) so concurrent requests don't all rebuild. Cache the "checked" state per request so a search doesn't add two queries every time.
2. Add a `## Multi-server deployments` note to `docs/advanced.md` or `docs/troubleshooting.md`. Explain that the index self-heals from the database, that the on-disk snapshot is per node, and when `index.path` should point at shared storage.

**Tests**
- With topics in the DB and a fresh empty index (new `SqliteFtsIndex` on a new temp path bound into the container), `specification()->search( 'doctype' )` returns a hit and `index->version()` equals the current snapshot version afterwards.
- With an index whose version already matches, no rebuild happens. Spy on or count `rebuild` calls with a fake `SearchIndex`.

### M4 — Sync can fail half-applied with a raw `QueryException`; column lengths are unvalidated

**Where** `src/Okf/Synchronizer.php:150-158`, `src/Okf/TopicParser.php:121-132`, `database/migrations/2026_10_10_000001_create_specification_topics_table.php:26-36`, `src/Console/Commands/SpecSyncCommand.php:66-72`

**Problem**
- The parser accepts unbounded `title` (column `varchar(255)`), `conformance` (`varchar(16)`), and front-matter `resource` (`varchar(512)`). On MySQL strict mode or PostgreSQL, one oversized value makes the whole transaction throw a `QueryException`, not a per-topic error. SQLite ignores the lengths, so tests can't catch this. Current upstream maximums are title 105, conformance 8 (`MUST NOT`), and URL about 70, so this is latent, not live.
- `perform()` writes the new snapshot to disk **before** the DB transaction. A DB failure leaves disk on the new version and the DB and index on the old one. It self-heals on the next sync, but the exception that escapes is not a `SpecificationException`. `keystone:spec-sync` therefore crashes with a stack trace instead of its formatted error, and callers catching `SpecificationException` miss it.

**Fix**
1. `TopicParser::parse()`: throw `InvalidArchiveException` (making it a per-topic error) when `mb_strlen( title ) > 255`. Treat `conformance` longer than 16 characters, or not one of `MUST`, `MUST NOT`, `SHOULD`, `SHOULD NOT`, `MAY`, as `null`. `Attribution::canonicalUrl()` (from H2) should also fall back when `strlen( $url ) > 512`.
2. `Synchronizer::perform()`: run `$this->loader->load()`, then the DB transaction, then `$this->store->write()` (disk last). Wrap the transaction and the index rebuild in `try/catch ( Throwable $e )`. Rethrow `SpecificationException` as is, and wrap anything else in `SyncFailedException( __( 'Could not apply the specification snapshot: :message', … ), previous: $e )`.

**Tests**
- A topic with a 300-character title lands in `SyncResult::$errors`, and the other topics still sync.
- `conformance: "SOMETHING VERY LONG"` stores `null`.
- A forced DB failure (e.g. drop the `specification_snapshots` table in the test) makes `sync()` throw `SyncFailedException`, and the snapshot on disk is unchanged (the manifest version equals the previous version).

### M5 — `agent_readiness_experimental` config is dead

**Where** `config/artisanpack/specification.php:117-126`, `docs/installation/configuration.md:86`, `docs/advanced/authoring-checks.md:191`

**Problem**

## Low

### L1 — Rendered HTML injects an `<h1>` and has no `lang`

**Where** `src/Attribution/RenderedTopic.php:77-85`

Every upstream body starts with `# <Title>`, so rendering a topic inside an admin page adds a second `<h1>` and breaks the heading outline (WCAG 1.3.1 / 2.4.6 best practice). The content is English, so in a localized host app it needs `lang="en"` (WCAG 3.1.2, Language of Parts).

**Fix**
- Add `lang="en"` and `dir="ltr"` to the `.spec-topic` wrapper.
- Add a `render.heading_offset` config (default `1`) applied through a `DocumentParsedEvent` listener that does `Heading::setLevel( min( 6, $level + $offset ) )`. Document it in `docs/usage/rendering-topics.md`.

**Tests** cover that the wrapper has `lang="en"`, that `# Title` renders as `<h2>` by default, and that an offset of `0` keeps `<h1>`.

### L2 — Attribution quote marks are outside the translatable string

**Where** `src/Attribution/Attribution.php:135-139`, `:153-157`

The `“…”` marks are concatenated in PHP, so translators can't localise them (e.g. `«…»`, `„…“`). Move them into the strings: `__( '“:title” from :source, licensed under :license.' )` for both HTML and Markdown. Update the tests that assert the exact output.

### L3 — MCP client limits and error-message cast

**Where** `src/Mcp/HttpMcpClient.php:88-97`, `:124-135`, `:234`

- `listTopics()` documents `limit` 1–200 and `getChanges()` documents 1–100, but neither clamps the value (only `search()` does). Clamp them the same way as `search()`.
- `(string) ( $message['error']['message'] ?? … )`: if the server sends an array or object, PHP raises "Array to string conversion", which Laravel turns into `ErrorException`. Use `is_string( … ) ? … : __( 'Unknown error' )`.

Add tests for both.

### L4 — SQLite index has no busy timeout or WAL

**Where** `src/Search/SqliteFtsIndex.php:210-212`

A search that runs while another process holds the rebuild transaction fails immediately with `database is locked` and becomes a `SearchIndexUnavailableException`. After opening the connection, add `PDO::ATTR_TIMEOUT => 5` and execute `PRAGMA journal_mode=WAL` (skip this for `:memory:`) and `PRAGMA busy_timeout=5000`. Add a test asserting that `PRAGMA journal_mode` reports `wal` for a file-backed index.

### L5 — Tokenizer splits words with combining marks

**Where** `src/Search/SqliteFtsIndex.php:183`

`/[\p{L}\p{N}]+/u` breaks words that contain combining marks (Devanagari, decomposed accents) into fragments. Use `/[\p{L}\p{M}\p{N}]+/u`. Test that `matchExpression( 'हिन्दी' )` yields a single quoted token.

### L6 — `keystone:spec-diff` default `since`

**Where** `src/Console/Commands/SpecDiffCommand.php:102`, `src/Mcp/HttpMcpClient.php:126-128`

The fallback `since` is `synced_at` in the app timezone, truncated to a date by `getChanges()`. Upstream dates are UTC days. Convert with `->utc()` before truncating (in `getChanges()` for any `DateTimeInterface`). Document that the day of the last sync is included. Add a test with app timezone `America/Chicago` and `synced_at` at 23:30 local, asserting that the UTC date is sent.

### L7 — `keystone:spec-check` checks error pages silently

**Where** `src/Console/Commands/SpecCheckCommand.php:123-132`

A 404 or 500 response body is fed to the Page checks without warning. When `$response->status() >= 400`, print `components->warn( __( 'The URL returned HTTP :status; page checks ran against the error response.', … ) )`. Test it with `Http::fake` returning 500.

### L8 — Fold the pre-release `changes` column migration

**Where** `database/migrations/2026_10_10_000003_add_changes_to_specification_snapshots_table.php`

1.0.0 has no installed base, so shipping a create migration plus an alter migration for the same release only adds noise. Move `$table->json( 'changes' )->nullable();` into `2026_10_10_000002_create_specification_snapshots_table.php` after `topic_count`, and delete migration 000003. Note for the dev app: it has already run 000003, so after this change run `php artisan migrate:fresh` there (or roll back first). Confirm with the user before touching the dev app database. Keep `ServiceProviderTest` "creates the topics and snapshots tables" passing, and assert the `changes` column exists.

## Info (no code change unless the owner decides otherwise)

- **I1 — Laravel 13 only.** `composer.json` requires `illuminate/*: ^13.0`, but the ecosystem blueprint guideline says packages support L10–12. This matches the newer satellite packages (e.g. ecommerce on L13), so confirm it is intentional and keep `docs/installation/requirements.md` as is.
- **I2 — `artisanpack-ui/core` is required but unused.** This is per the blueprint convention, so leave it.
- **I3 — Streaming size caps are untested against a real transport.** The `on_headers` and `progress` guards in `OkfDownloader` and `HttpMcpClient` are bypassed by `Http::fake()`. Before tagging, optionally verify manually that an exception thrown from Guzzle's `progress` callback aborts the curl transfer and is unwrapped to `SyncFailedException` / `McpRequestException`, e.g. with `php -S` serving a 20 MB file and `SPECIFICATION_OKF_URL` pointing at it through an https tunnel. No change expected.
- **I4 — Verified sound (no action):**
  - Tar reader: header checksums, octal parsing, truncation, entry and size caps; symlinks, hard links, and devices ignored.
  - Path allow-list (`FILE_PATTERN` / `TOPIC_PATTERN`) blocks `../`, absolute paths, and odd names before anything reaches disk. Slugs come from paths, never from front matter.
  - Snapshot swap is atomic with restore on failure.
  - FTS5 MATCH input is reduced to quoted word tokens, so no query-syntax injection.
  - Markdown renders with `html_input: escape` and `allow_unsafe_links: false`. `body_md` is hidden from model serialization. `RenderedTopic` exposes no body-only accessor.
